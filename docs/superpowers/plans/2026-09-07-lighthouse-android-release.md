# LIGHTHOUSE Android Owner-Test Release Spine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Package the Owner-approved `lighthouse-next/` UI as a signed, identity-verified LIGHTHOUSE Android owner-test APK that preserves the existing Android package/signer continuity and can be tested by installing a higher-version candidate over an earlier canonical installation.

**Architecture:** Migrate only the reusable Android packaging/security/signing infrastructure from `feat/lighthouse-1.0.0-rebuild` into the current `work/metro-new-20260906` branch. The Android shell stages an explicit allowlist of `lighthouse-next/` runtime files into Capacitor `www/`, generates native launcher resources from the approved lighthouse artwork, applies the existing Android security baseline, builds/signs the APK, and verifies package/signer/version/hash/provenance before uploading an owner-test artifact. Legacy root UI, patch runtime, updater code, and production publication remain outside this phase.

**Tech Stack:** Node.js 22, Capacitor 8.5.0, Java 21, Android Gradle toolchain generated by Capacitor, Node built-in test runner, `sharp` 0.34.3 for deterministic launcher rasterization, GitHub Actions, Android `zipalign`, `apksigner`, and `aapt`.

**Spec:** `docs/superpowers/specs/2026-09-07-lighthouse-android-release-architecture-design.md`

## Global Constraints

- Application ID remains `com.yggdrasil.lighthouse`.
- APK signer certificate SHA-256 remains `aae608a7ddab0dbfccc1d35e817c5683b3c64b90ab581a4b74867db54e0351ce`.
- Android `versionCode` is a monotonic increasing integer; first owner-test candidate in this plan is `1006`, which is greater than repository donor baseline `1005`. - Product UI/logic source is `lighthouse-next/` only.
- Approved launcher identity source is `lighthouse-next/assets/lighthouse-icon.svg`; `lighthouse-next/assets/lighthouse-icon-maskable.svg` defines the already-approved safe-area treatment.
- Do not redesign the Owner-approved visual direction during packaging.
- Do not implement in-app updater or patch updater in this plan.
- Do not create a production release, merge, publish to a store, or cut over automatically.
- CI PASS does not imply physical-device PASS. Install-over, data persistence, launcher crop, and launch behavior remain VERIFY until observed on the Owner device.

The implementation must:

```js
import { cp, mkdir, rm, stat } from 'node:fs/promises';
import { join } from 'node:path';

async function exists(path) {
  try { await stat(path); return true; } catch { return false; }
}

export async function stageLighthouseNext({ repoRoot, shellRoot }) {
  const sourceRoot = join(repoRoot, 'lighthouse-next');
  const wwwRoot = join(shellRoot, 'www');
  for (const relative of RUNTIME_FILES) {
    if (!(await exists(join(sourceRoot, relative)))) {
      throw new Error(`LIGHTHOUSE_NEXT_SOURCE_MISSING:${relative}`);
    }
  }
  if (!(await exists(join(sourceRoot, 'assets/lighthouse-icon.svg')))) {
    throw new Error('LIGHTHOUSE_NEXT_SOURCE_MISSING:assets/lighthouse-icon.svg');
  }
  if (!(await exists(join(sourceRoot, 'assets/lighthouse-icon-maskable.svg')))) {
    throw new Error('LIGHTHOUSE_NEXT_SOURCE_MISSING:assets/lighthouse-icon-maskable.svg');
  }

  await rm(wwwRoot, { recursive: true, force: true });
  await mkdir(wwwRoot, { recursive: true });
  for (const relative of RUNTIME_FILES) {
    await cp(join(sourceRoot, relative), join(wwwRoot, relative), { force: true });
  }
  await cp(join(sourceRoot, 'assets'), join(wwwRoot, 'assets'), { recursive: true, force: true });
  return { stagedFiles: [...RUNTIME_FILES, 'assets/'] };
}
```

The CLI entrypoint resolves `repoRoot` as the parent of `android-shell` and calls the exported function. It must not copy `preview.html`, `preview.css`, root `app.mjs`, root `styles.css`, `greenfield/`, `lighthouse/`, `ui/`, or any patch/trusted/bootstrap runtime.
