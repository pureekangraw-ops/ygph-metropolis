## Recommended option: two unchanged formats on the existing service

Preserve native GeoJSON/pin journal and Studio graph/package store separately. Add only the missing owner-selected GeoJSON Snapshot/proposal transport on the existing GOVIEW Worker/R2 and named GO binding, using the existing captureId/baseVersion proposal envelope and exact-byte hashes/receipts. Keep Studio routes and package schema intact. Keep GPS/history outside the payload. Preserve original local field records; imported claims remain claims. No arbitrary conversion, unified map schema, new database, Worker or paid service is needed by this option.

This is a proposed coordinated implementation, not a current capability or approved contract. The contract decision must define: separate artifact routing/type validation, immutable identity/digest/correlation binding, an owner-triggered Android upload authority narrower than GO_WRITE_TOKEN, GO read/propose operations, exact proposal download, and distinct Upload/Download/Update receipts. Do not embed/reuse GO_WRITE_TOKEN in Android or silently broaden ANDROID_READ_TOKEN. Reuse existing R2 storage only after the relevant authority and runtime/cost approval; existing service use can still incur storage/request costs. No endpoint or schema change has been implemented here.

Ownership/dependencies: GOVIEW owns outsideview Activity/exchange/validation/storage and tests; existing Worker/GO owner must own or explicitly coordinate `goview-package-bridge/{worker,go-adapter,entry}.mjs`, role contract and R2 namespace. GO owner must register and validate added tool calls in `Go-Together/worker/{goview-direct.mjs,index.js}` and coordinate service-binding configuration. Browser owns StationHttp/shared transport changes; this option does not currently require StationHttp edits. Static Studio engine/assets are outside this lane's narrow native ownership and need coordination if changed; none are required merely to retain the current format.

Impact: completes the missing selected-pin transfer leg while preserving both editors and all existing maps; moderate coordinated client/Worker/GO work and separate runtime acceptance. Does not promise a single fused map or field-confirmed record replacement. User approval remains required before any returned proposal mutates local data.

## Alternative: explicit two-file handoff now

Keep selected `.geojson` and saved `.goview.json` as separate owner-selected files; supply only chosen copies to GO and import its returned matching format through the existing preview/approval path. Retain originals/backups. No backend/auth/schema implementation change or new runtime activation required. Impact: least risk and preserves formats, but selection/file handoff and receipt return remain manual; automatic Snapshot→GO→Download remains incomplete. No claim that a local document export itself constitutes Upload or GO receipt.

## Minimum coordinated implementation, only after decision

1. Agree the narrowly scoped selected-artifact transport/authority contract with Worker/GO owners. Preserve the existing local GeoJSON envelope and Studio schema. Specify independent artifact identity, type, size limits, captureId/baseVersion/full-byte digest, immutable retry behavior and role boundaries before implementation. Do not treat configuration as sufficient to add Android upload permission.
2. In the existing Worker/R2 adapter, add only validated selected-GeoJSON storage/read/proposal operations with a separate namespace/type boundary; retain existing Studio routes, immutable objects and Direct behavior. No broad listing, deletion or generic object-store access is needed.
3. In existing GO dispatch, expose only explicitly selected-artifact read and bounded proposal operations through the existing named binding and owner authentication. GO receives no access to the whole phone journal, location history or arbitrary files.
4. In GOVIEW's existing exchange/Activity paths, add explicit owner-triggered upload and exact proposal download. Feed downloaded bytes through `GoviewSandboxContract.readFile`, current capture/revision preview checks, and current owner-approved Update. Persist transfer receipts separately from local save/readback receipts. Do not auto-approve, auto-upload on resume, replay uncertain mutations, or alter Studio routing.
5. Add focused synthetic client/Worker/GO contract tests and Android state/readback coverage. Configuration, credential provisioning and runtime activation remain separate approval gates; do not include them in a development-only PR.

## Data minimization and proof gates

- **Payload gate:** select named pins explicitly; prove omitted pins, notes, private field evidence, GPS/live viewport and location history are absent. Preserve the original local records and backups. Selected sharing remains intentionally reduced; full native export/backup is a different action.
- **Authority gate:** prove Android upload cannot publish arbitrary GO packages, overwrite proposals or use GO_WRITE_TOKEN; existing Android read role remains read-only. Prove GO cannot fetch unselected phone data or commit local maps.
- **Transfer gate:** independently read exact stored bytes/digest after upload; bind capture, version and correlation. Failed/ambiguous writes require readback, not a fabricated success receipt or automatic replay. Malformed, oversized, wrong-format, cross-role and substituted artifacts fail closed.
- **Approval gate:** Download and Preview leave pins unchanged; cancel is inert; wrong capture, stale base, duplicate and same-ID conflict behave distinctly. Only owner Update approval commits through the existing store, preserving unrelated/field-confirmed records. Remote receipt never implies local save.
- **Durability gate:** verify save/readback, receipt separation, actual process stop/restart, backup restore and retained rollback copy. Failed commit versus committed-but-unverified readback must remain distinguishable. Keep Studio package and graph roundtrip/routing tests as regressions.
- **Real acceptance gate:** after separate compatible-build and runtime authorization, run the complete synthetic selected-artifact GO-to-phone roundtrip and inspect the owner's actual device receipt and retained data. Emulator/local/CI passes cannot replace that evidence; no real GPS or private map transmission is authorized by this plan.
